## Assumptions (smallest reversible)

- A1: discovery mode (`paths=None`) scans `*.yaml|*.yml|*.json`, skips hidden dirs + `node_modules`/`__pycache__`/`site-packages`; keeps files passing gate, plus malformed files with `openapi:` marker text. NOT_OPENAPI files dropped silently. Explicit `paths` → every file reported, NOT_OPENAPI incl.
- A2: version must be string `MAJOR.MINOR.PATCH[-pre]`. YAML `openapi: 3.1` (float) → INVALID_VERSION. Unknown patch in supported family (e.g. `3.1.9`) accepted.
- A3: no version-mismatch validation (e.g. `webhooks` in 3.0) — model records as-is; checks belong to spec 005.
- A4: cross-file targets loaded lazily as FRAGMENT docs; fragments never extracted as roots. Refs resolved against referring file dir; `$id`-based base URIs ignored.
- A5: plain-name fragments (`#anchor`, 3.1 `$anchor`) → INVALID, not resolved. `$dynamicRef`/`$recursiveRef` → DYNAMIC (target UNKNOWN).
- A6: refs/extensions ignored inside data: `example`, `default`, `enum`, `const`, JSON Schema `examples` arrays, Example Object `value`/`dataValue`/`serializedValue`, `x-*` values. Keys of name maps (`properties`, `content`, `headers`, `components/*`, `scopes`, …) are names, not keywords → property named `$ref`/`x-foo` ≠ ref/extension.
- A7: cycle = SCC over ref graph (node = ref target; edge = ref site inside target subtree). ALIAS = every member is pure `$ref` object (unresolvable); RECURSIVE = valid recursive structure (tree schema). One `ReferenceCycle` per SCC, members sorted; location = first sorted closing ref site.
- A8: `deref` follows ≤64 hops with visited set; loops/misses/external → element kept with `ref`, resolved fields None, no operations from unresolved path items.
- A9: operations collected from paths, webhooks, operation callbacks (recursive callbacks guarded by visited set), 3.2 `query` + `additionalOperations`. Component `pathItems`/component callbacks not expanded into operations (no concrete path). Fallback identity for non-path ops: `method_path:POST webhook:{name}` / `callback:{expression}`.
- A10: `schemas` = component schemas only (inline schemas kept inside parameter `schema` / raw content). `external_docs` collected at root, tags, operations, top-level component schemas.
- A11: security requirement schemes stored as `(name, scopes)` values, not mapping keys — key-based secret redaction would mask scheme names like `apiKey`.
- A12: `operation.parameter_pointers` etc. are pointers inside the operation's own document.

## Open risks

- R1: `Model.to_dict` redaction masks raw-fragment values under secret-looking keys (schema property `password`, `access_token`, server variable `token`). In-memory model intact; serialized model loses that fragment detail, round-trip not exact for such specs. Needs product decision (redaction exemption for structural keys vs. keep always-on).
- R2: JSON source locations rely on YAML re-parse; JSON that YAML rejects gets document-level locations only (no line).
- R3: pure-Python PyYAML ≈ seconds for multi-MB specs; CSafeLoader not used (C composer recursion depth unverified).
- R4: `MAX_DEPTH=256` / `MAX_NODES=250k` limits are guesses; very large real specs could hit node cap (reported MALFORMED, not crash).
- R5: no OAS001 emission here; consumers map `DocumentStatus`/`IssueCode` to findings in spec 005.
- R6: unrelated pre-existing working-tree changes (`factory/specs/inbox/01x-*.md`, `.claude/`) untouched.
